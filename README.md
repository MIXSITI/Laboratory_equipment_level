# Система бронирования лабораторного оборудования

Консольное приложение на языке Python для автоматизации учета лабораторного
оборудования, контроля квалификационного допуска пользователей и управления
процессом бронирования приборов учебно-научной лаборатории.

В рамках **Практической работы № 3 (ПР3)** осуществлен полноценный переход от
функциональной модели (коллекций словарей ПР2) к объектно-ориентированной модели:
основные сущности предметной области представлены классами, поведение инкапсулировано
в методах, реализовано объектное связывание (композиция), наследование и полиморфизм.

## Назначение

Приложение предназначено для автоматизации учета, проверки готовности и
бронирования лабораторного оборудования. Система исключает накладки в
расписании, контролирует уровень допуска исследователей и факт прохождения
инструктажа по технике безопасности, а также рассчитывает стоимость аренды
с учетом льготных скидок для студентов.

## Целевая аудитория

- Студенты и аспиранты, выполняющие лабораторные работы и научные исследования.
- Преподаватели и научные руководители, планирующие практические занятия.
- Администраторы и лаборанты, отвечающие за исправность приборов, проведение
  инструктажей и допуск пользователей.

## Предметная область и сущности проекта

Предметная область охватывает процесс регламентированного бронирования исследовательского
оборудования учебно-научной лаборатории (спектрофотометры, электронные микроскопы,
осциллографы, 3D-принтеры).

В проекте выделены **4 основные сущности предметной области**:
1. **Пользователь (`User`)** — субъект, работающий с оборудованием (студент или сотрудник,
   квалификационный уровень допуска 1–3, отметка о прохождении инструктажа по ТБ).
2. **Оборудование (`Equipment`)** — физический прибор или стенд (инвентарный номер,
   исправность, нахождение на ТО, требуемый уровень допуска, почасовая ставка аренды).
3. **Период (`Period`)** — интервал времени бронирования (календарная дата и
   длительность работы в часах). В соответствии с предметной областью **период отдельно в
   самостоятельную модель/файл не выносится**, а инкапсулирован внутри сущности Бронирование.
4. **Бронирование (`Booking`)** — факт регистрации заявки на прибор конкретным пользователем
   на заданный период с расчетом итоговой стоимости.

Правила предметной области:
- один прибор не может иметь двух активных бронирований на одну и ту же дату;
- отмененное бронирование сохраняется в базе для аудита, но освобождает дату для новых заявок;
- для студентов предоставляется скидка 50% на почасовую ставку.

## Объектная модель (ООП)

### 1. `Equipment` — лабораторное оборудование (`models/equipment.py`)
Описывает физический прибор лаборатории.
- **Основные атрибуты:**
  - `id: int` — уникальный идентификатор прибора;
  - `name: str` — наименование оборудования;
  - `inventory_number: str` — инвентарный номер (например, `EQ-301`);
  - `operational: bool` — флаг исправности прибора;
  - `under_maintenance: bool` — флаг нахождения на ТО;
  - `required_level: int` — требуемый уровень допуска (1–3);
  - `hourly_rate: float` — базовая стоимость аренды (руб/час).
- **Методы и свойства:**
  - `@property is_ready -> bool` — свойство готовности оборудования к работе;
  - `check_readiness() -> str` — текстовый статус технического состояния;
  - `is_suitable_for_level(user_level: int) -> bool` — проверка допуска;
  - `@staticmethod validate_rate(rate: float) -> bool` — валидация почасовой ставки;
  - `@staticmethod validate_level(level: int) -> bool` — валидация уровня допуска;
  - `@classmethod from_data(data: dict) -> Equipment` — фабричный метод создания объекта из JSON;
  - `to_dict() -> dict` — сериализация объекта в словарь для JSON;
  - `__str__() -> str` — строковое представление оборудования.

### 2. `User` — пользователь системы (`models/users.py`)
Базовый класс пользователя лаборатории.
- **Основные атрибуты:**
  - `id: int` — уникальный идентификатор пользователя;
  - `name: str` — ФИО пользователя;
  - `role: str` — статус пользователя («студент» или «сотрудник»);
  - `access_level: int` — квалификационный уровень допуска (1–3);
  - `briefing_passed: bool` — отметка о прохождении инструктажа по ТБ;
  - `email: str` — контактный адрес электронной почты.
- **Методы и наследование:**
  - `has_access(required_level: int) -> bool` — проверка допуска с учетом ТБ;
  - `is_student() -> bool` — проверка роли студента;
  - `get_discount() -> float` — полиморфный метод расчета скидки;
  - `@staticmethod validate_level(level: int) -> bool` — валидация уровня допуска;
  - `@classmethod from_data(data: dict) -> User` — создание соответствующего подкласса (`Student` / `Staff`);
  - `to_dict() -> dict` — сериализация профиля пользователя;
  - `__str__() -> str` — строковое представление пользователя.

#### Иерархия наследования и полиморфизм:
- **`Student(User)`** — подкласс студента. Переопределяет `get_discount() -> 0.5` (скидка 50%).
- **`Staff(User)`** — подкласс сотрудника. Переопределяет `get_discount() -> 0.0` (полная ставка).

### 3. `Period` — период бронирования (`models/bookings.py`)
Описывает временной интервал резервирования прибора (дата `date` и длительность в часах `duration_hours`).
Логически входит в состав бронирования и отдельно в файл модели не выносится.

### 4. `Booking` — бронирование (`models/bookings.py`)
Описывает факт резервирования прибора пользователем на заданный период.
Реализует **композицию объектов**, сохраняя ссылки на объекты `Equipment`, `User` и инкапсулируя `Period`.
- **Основные атрибуты:**
  - `id: int` — номер заявки;
  - `equipment: Equipment` — ссылка на объект оборудования;
  - `period: Period` — объект периода (`booking_date: date`, `duration_hours: float`);
  - `user: User` — ссылка на объект пользователя;
  - `cost: float` — рассчитанная стоимость бронирования;
  - `is_cancelled: bool` — статус отмены заявки (по умолчанию `False`).
- **Методы и свойства:**
  - `cancel() -> None` — отмена бронирования (изменяет состояние, не удаляя объект);
  - `@property status -> str` — статус («Подтверждено» / «Отменено»);
  - `to_dict() -> dict` — сериализация заявки с сохранением `equipment_id` и `user_id`;
  - `__str__() -> str` — строковое представление бронирования.

## Хранение данных (JSON)

Данные приложения сохраняются в текстовых файлах формата JSON в каталоге `data/`.
При запуске функции модуля `storage.py` загружают структуры JSON и создают объекты
соответствующих классов, а при выходе — сериализуют объекты обратно в JSON.

### `data/equipment.json`
```json
[
  {
    "id": 1,
    "name": "Спектрофотометр UV-1800",
    "inventory_number": "EQ-301",
    "operational": true,
    "under_maintenance": false,
    "required_level": 2,
    "hourly_rate": 1200.0
  }
]
```

### `data/users.json`
```json
[
  {
    "id": 1,
    "name": "Иванов Алексей Сергеевич",
    "role": "студент",
    "access_level": 2,
    "briefing_passed": true,
    "email": "ivanov@edu.mirea.ru"
  }
]
```

### `data/bookings.json`
```json
[
  {
    "id": 1,
    "equipment_id": 1,
    "user_id": 1,
    "booking_date": "2026-07-15",
    "duration_hours": 3.0,
    "cost": 1800.0,
    "is_cancelled": false
  }
]
```

## Структура проекта

Структура полностью соответствует архитектурному стандарту методических указаний:

```text
work/
│
├── README.md                  # Документация проекта
├── requirements.txt           # Инструменты разработки (pytest, flake8)
├── main.py                    # Точка входа в программу, главное меню
├── storage.py                 # Сохранение и загрузка объектов в JSON
├── utils.py                   # Валидация ввода, интроспекция, декораторы
│
├── models/                    # Пакет объектной модели предметной области
│   ├── __init__.py            # Экспорт классов Equipment, User, Student, Staff, Booking, Period
│   ├── equipment.py           # Класс Equipment и функции работы с приборами
│   ├── bookings.py            # Классы Booking, Period и функции управления бронированием
│   └── users.py               # Классы User, Student, Staff и функции пользователей
│
├── data/                      # Персистентное файловое хранилище JSON
│   ├── equipment.json         # Каталог лабораторных приборов
│   ├── bookings.json          # База заявок на бронирование
│   └── users.json             # Реестр пользователей системы
│
└── tests/                     # Автоматизированные тесты pytest
    ├── test_equipment.py      # Модульные тесты класса Equipment и функций оборудования
    ├── test_bookings.py       # Модульные тесты класса Booking, периода и хранилища
    └── test_users.py          # Модульные тесты классов User, Student, Staff
```

## Требования к окружению

- Python 3.10+;
- pytest >= 8.0;
- flake8 >= 7.0.

Установка зависимостей:
```bash
pip install -r requirements.txt
```

## Запуск программы

```bash
python main.py
```

## Запуск автоматизированных тестов

Все ключевые сценарии объектной модели, валидация, отмена заявок, инкапсуляция,
наследование и полиморфизм протестированы набором из 35 автоматических тестов:



```bash
python tests/test_equipment.py
python tests/test_bookings.py
python tests/test_users.py
```
