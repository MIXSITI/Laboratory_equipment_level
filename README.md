# Система бронирования помещений и оборудования

Консольное приложение на языке Python для автоматизации учета помещений и
лабораторного оборудования, контроля квалификационного допуска пользователей и
управления процессом бронирования.

В рамках **Практической работы № 3 (ПР3)** осуществлен полноценный переход от
функциональной модели (коллекций словарей ПР2) к объектно-ориентированной модели:
основные сущности предметной области представлены классами, поведение инкапсулировано
в методах, реализовано объектное связывание (композиция), наследование и полиморфизм.

## Назначение

Приложение предназначено для автоматизации учета, проверки готовности и
бронирования помещений и исследовательского оборудования. Система исключает накладки в
расписании, контролирует уровень допуска исследователей и факт прохождения
инструктажа по технике безопасности, а также рассчитывает стоимость аренды
с учетом льготных скидок для студентов.

## Целевая аудитория

- Студенты и аспиранты, выполняющие лабораторные работы и научные исследования.
- Преподаватели и научные руководители, планирующие практические занятия.
- Администраторы и лаборанты, отвечающие за исправность приборов, проведение
  инструктажей и допуск пользователей.

## Предметная область

Предметная область охватывает процесс регламентированного бронирования помещений
и оборудования учебно-научной лаборатории (спектрофотометры, электронные
микроскопы, осциллографы, 3D-принтеры).
Ключевые аспекты:
- учет технического состояния и вместимости помещений/приборов;
- контроль прав доступа пользователя (наличие инструктажа по ТБ, квалификационный
  уровень допуска от 1 до 3);
- расчет стоимости использования прибора со скидкой 50% для студентов;
- создание, учет и отмена бронирований на определенные даты;
- одно помещение не может иметь двух активных бронирований на одну и ту же дату;
- отмененное бронирование сохраняется в базе для аудита, но освобождает дату для новых заявок.

## Основные сущности и объектная модель (ООП)

### 1. `Room` — помещение / оборудование (`models/rooms.py`)
Описывает помещение или физический прибор лаборатории.
- **Основные атрибуты:**
  - `id: int` — уникальный идентификатор;
  - `name: str` — наименование помещения / оборудования;
  - `capacity: int` — вместимость (количество человек);
  - `inventory_number: str` — инвентарный номер;
  - `operational: bool` — флаг исправности;
  - `under_maintenance: bool` — флаг нахождения на ТО;
  - `required_level: int` — требуемый уровень допуска (1–3);
  - `hourly_rate: float` — базовая стоимость аренды (руб/час).
- **Методы и свойства:**
  - `is_suitable_for(people_count: int) -> bool` — проверка вместимости;
  - `@property is_ready -> bool` — свойство готовности к работе;
  - `check_readiness() -> str` — текстовый статус технического состояния;
  - `is_suitable_for_level(user_level: int) -> bool` — проверка уровня допуска;
  - `@staticmethod validate_capacity(capacity: int) -> bool` — валидация вместимости;
  - `@staticmethod validate_rate(rate: float) -> bool` — валидация почасовой ставки;
  - `@staticmethod validate_level(level: int) -> bool` — валидация уровня допуска;
  - `@classmethod from_data(data: dict) -> Room` — фабричный метод создания объекта из JSON;
  - `to_dict() -> dict` — сериализация объекта в словарь для JSON;
  - `__str__() -> str` — строковое представление объекта.

### 2. `User` — пользователь системы (`models/users.py`)
Базовый класс субъекта, работающего с системой.
- **Основные атрибуты:**
  - `id: int` — уникальный идентификатор пользователя;
  - `name: str` — ФИО пользователя;
  - `role: str` — статус пользователя («студент» или «сотрудник»);
  - `access_level: int` — квалификационный уровень допуска (1–3);
  - `briefing_passed: bool` — отметка о прохождении инструктажа по ТБ;
  - `email: str` — контактный адрес электронной почты.
- **Методы и наследование:**
  - `has_access(required_level: int) -> bool` — проверка допуска с учетом ТБ;
  - `is_student() -> bool` — проверка роли студента;
  - `get_discount() -> float` — полиморфный метод расчета скидки;
  - `@staticmethod validate_level(level: int) -> bool` — валидация уровня допуска;
  - `@classmethod from_data(data: dict) -> User` — создание соответствующего подкласса (`Student` / `Staff`);
  - `to_dict() -> dict` — сериализация профиля пользователя;
  - `__str__() -> str` — строковое представление пользователя.

#### Иерархия наследования и полиморфизм:
- **`Student(User)`** — подкласс студента. Переопределяет `get_discount() -> 0.5` (скидка 50%).
- **`Staff(User)`** — подкласс сотрудника. Переопределяет `get_discount() -> 0.0` (полная ставка).

### 3. `Booking` — бронирование (`models/bookings.py`)
Описывает бронирование помещения / оборудования конкретным пользователем на определенную дату.
Реализует **композицию объектов**, сохраняя ссылки на объекты `Room` и `User`.
- **Основные атрибуты:**
  - `id: int` — номер заявки;
  - `room: Room` — ссылка на объект помещения (псевдоним `equipment`);
  - `booking_date: date` — календарная дата бронирования;
  - `user: User` — ссылка на объект пользователя;
  - `duration_hours: float` — длительность сеанса в часах;
  - `cost: float` — стоимость бронирования;
  - `is_cancelled: bool` — статус отмены заявки (по умолчанию `False`).
- **Методы и свойства:**
  - `cancel() -> None` — отмена бронирования (изменяет состояние объекта, не удаляя его);
  - `@property status -> str` — статус («Подтверждено» / «Отменено»);
  - `to_dict() -> dict` — сериализация заявки в формат с сохранением `room_id` и `user_id`;
  - `__str__() -> str` — строковое представление бронирования.

## Хранение данных (JSON)

Данные приложения сохраняются в текстовых файлах формата JSON в каталоге `data/`.
При запуске функции модуля `storage.py` загружают структуры JSON и создают объекты
соответствующих классов, а при выходе — сериализуют объекты обратно в JSON.

### `data/rooms.json`
```json
[
  {
    "id": 1,
    "name": "Спектрофотометр UV-1800",
    "capacity": 5,
    "inventory_number": "EQ-301",
    "operational": true,
    "under_maintenance": false,
    "required_level": 2,
    "hourly_rate": 1200.0
  }
]
```

### `data/users.json`
```json
[
  {
    "id": 1,
    "name": "Иванов Алексей Сергеевич",
    "role": "студент",
    "access_level": 2,
    "briefing_passed": true,
    "email": "ivanov@edu.mirea.ru"
  }
]
```

### `data/bookings.json`
```json
[
  {
    "id": 1,
    "room_id": 1,
    "equipment_id": 1,
    "user_id": 1,
    "booking_date": "2026-07-15",
    "duration_hours": 3.0,
    "cost": 1800.0,
    "is_cancelled": false
  }
]
```

├── data/                      # Персистентное файловое хранилище JSON
│   ├── rooms.json             # Данные о помещениях и оборудовании
│   ├── bookings.json          # База заявок на бронирование
│   └── users.json             # Реестр пользователей системы

└── tests/                     # Автоматизированные тесты pytest
    ├── test_rooms.py          # Тесты класса Room и функций помещений

    └── test_users.py          # Тесты классов User/Student/Staff и пользователей

## Требования к окружению

- Python 3.10+;

pip install -r requirements.txt
